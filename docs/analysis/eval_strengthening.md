### 해석: 최종 설정의 약점이 드러났다

- 전체로 보면 최종 설정이 여전히 낫다(완성도 MAE 0.462 → 0.077, 우선순위 0.775 → 0.825). 하지만 **새 경계 사례에서는 기준선보다 나빴다.**
- **문의를 버그로**: E-101(러닝머신 경로), E-107(AI 코치가 기록을 못 봄), E-108(위치 권한 '항상 허용' 안내)을 bug로 분류했다. 고장처럼 들리는 문의를 버그로 끌어가는 경향으로, v1에서 Few-shot 추가 뒤 E-021·E-052를 버그로 오분류한 것과 같은 방향이다.
- **P3를 P2로 과대평가**: E-109~E-112, E-114(카드 저장·음성 설정·지도 지연·AI 언어 등 부가 기능 문제)를 P2로 올렸다. v1 오류 분석에서 이미 다음 후보로 적은 "Rubric에 핵심 기능 범위가 없음" 문제가 새 데이터에서도 재현됐다.
- 복합 라벨에서 question을 빠뜨리는 경우가 늘었다(labels 0.925 → 0.867).
- 주의: 각 1회 실행이고 새 사례는 20건이라 1건이 5%p다. 다만 분류 2건 차이, 우선순위 5건 차이는 반복 실행에서 본 흔들림(1~3건)보다 크다.

### 다음 개선 후보 (효과 큰 순)

1. Rubric에 핵심 기능 범위를 적는다(거리·경로·기록 저장·로그인 = 핵심, 카드·음성·AI 코치·표시 = 부가). P3 → P2 과대평가를 겨냥한다.
2. 분류 Few-shot에 "고장처럼 들리지만 정상 동작을 묻는 문의" 예시를 추가하고, 분류 프롬프트에 RunBuddy의 현재 기능 목록(3초 카운트다운, 실내 러닝은 경로 없음 등)을 넣는다.
3. 복합 제보에서 질문 문장이 있으면 question 라벨을 함께 붙이는 규칙을 분명히 한다.
