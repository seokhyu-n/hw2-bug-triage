# Run-08 ~ Run-10: 새 경계 사례 개선 (dataset_v2, 120건)

기준: V2-Run-07 (Run-07 설정을 dataset_v2에 적용). 모두 Claude Haiku 5.5, 한 번에 한 변수만 바꿨다.
원본: `eval/runs.csv`, 사례별 `eval/results/V2-Run-0{8,9}.*`, `V2-Run-10.*`. 부분 집합 점수는
`python -m eval.subset_report V2-Run-07 V2-Run-08 V2-Run-09 V2-Run-10`.

"버그 놓침"은 정답이 bug인데 question/feature_request로 분류한 건수다. 버그가 묻히면 개발자가 보지
못하므로 이 과제에서 가장 피해야 할 오류로 본다.

## 해석

1. **Run-08 (`prompts/score_rubric.md`)**: Run-07에서 남은 실패 1순위가 부가 기능 과대평가였다
   (카드 저장 실패, 음성 설정, 지도 속도, AI 코치 언어를 P2로). "핵심 = 러닝을 기록하는 일"을 정의하고
   부가 기능 오동작은 크래시·데이터 손실이 아니면 P3로 정했다. 새 20건 우선순위 0.55 → 0.80, 기존 100건도
   0.88 → 0.91로 같이 좋아져 다른 사례를 해치지 않았다.
2. **Run-09 (`prompts/classify.md`)**: 고장처럼 들리는 문의(E-101 러닝머신 경로, E-107 AI 코치가 기록을 모름,
   E-108 '항상 허용' 권한)는 모델이 RunBuddy의 정상 동작을 몰라서 생긴 오류다. 정상 동작 6가지와 "이걸
   묻는 건 문의" 규칙을 넣자 세 건이 모두 맞았다. 하지만 규칙이 넓게 적용돼 "원래 이 정도 먹나요?"(배터리 과소모,
   E-016), "앱 왜이럼"(E-020) 같은 **진짜 버그가 문의로 바뀌었다**. 점수 합계만 보면 비슷하지만 오류의 종류가
   나빠졌다.
3. **Run-10 (`prompts/classify.md`)**: 예외를 "목록에 있는 동작"으로만 한정하고, 목록에 없는 현상은 "원래
   이런가요?"라고 물어도 비정상을 말하면 bug, 애매하면 bug로 정했다. 버그 놓침이 3 → 0으로 돌아왔고
   목표 3건은 유지됐다. 전체 분류 0.975, 우선순위 0.925로 dataset_v2에서 가장 좋은 설정이라 **최종 설정**으로
   삼았다.

## 남은 문제

- 분류 오류 3건: E-053(여러 질문이 섞인 긴 문의를 요청으로), E-113("기록 지우는 기능은 없나요? 지우고 싶어요"를
  문의로, 정답은 요청), E-116("비밀번호 보기 버튼 만들어 주세요. 눌러도 반응이 없어요"를 요청으로, 정답은 버그).
  모두 문장이 요청형인데 속뜻이 다른 경우다.
- 완성도 MAE 0.077 → 0.141. 같은 설정 반복 실행에서 0.07~0.18 범위로 흔들린 지표라 잡음으로 보지만, 확정하려면
  V2-Run-10을 반복 실행해야 한다.
- 각 Run은 1회 실행이다. 새 20건에서는 1건이 5%p다.
- 정상 동작 목록은 사람이 관리해야 한다. 서비스에서는 `data/faq.json`(신고 전 안내)과 같은 내용이라, 기능이
  바뀌면 두 곳을 같이 고쳐야 한다.
