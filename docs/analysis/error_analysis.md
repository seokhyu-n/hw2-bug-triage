## 3. 고른 개선과 이유

1. **개선1 (Run-06) - 추출 프롬프트: 문의·개선 요청도 feature_area를 채운다.** 유형 A가 가장 많고(13건) 원인이 프롬프트 정의 한 줄로 분명하다. 예시는 평가셋과 겹치지 않는 문장(CSV 내보내기, 500m 음성 안내, 위성 지도)으로 넣어 평가셋 누설을 피했다.
   - 결과: feature_area 누락 13→0, 추출 정확도 0.950→0.972. 부작용: 정답이 null인 E-006("안드로이드 7에서도 돌아가나요?"), E-096("꼭 업데이트 해야 하나요?")를 `other`로 채워 환각률 0.018→0.025. E-027·E-033·E-059·E-076은 구체 기능 대신 `other`가 됐다(누락 → 오답으로 바뀜). 순이익이 커서 유지.
2. **개선2 (Run-07) - Rubric: 원문에 크래시·로그인 불가·기록 유실이 있으면 영향 범위를 몰라도 P1.** 유형 B는 크래시·로그인 불가를 놓치는 위험한 오류라(긴급 건이 뒤로 밀림) 과대평가(C)보다 먼저 고쳤다. P2로 내리는 예외는 "수정 버전 배포 + 구형 OS 한정"이 모두 확인될 때만 쓰도록 문장을 좁혔다.
   - 결과: P1 재현율 10/16→15/16, 우선순위 exact 0.84→0.88, ±1 0.97→0.99. 부작용 1건: E-065(구형 기기에서 화면 끄면 기록 멈춤, 정답 P2)를 "기록 유실"로 보고 P1. 남은 P1 오류는 E-051(네트워크 오류 메시지를 로그인 불가로 보지 않음) 1건.
